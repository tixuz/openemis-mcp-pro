# OpenEMIS MCP Pro — Глоссарий терминов управления образованием

Этот глоссарий определяет основные термины, используемые в документации openemis-mcp-pro. Каждая статья объясняет понятие, как оно отражается в OpenEMIS, и содержит ссылку на соответствующий плейбук или ресурс.

---

### OpenEMIS

OpenEMIS — бесплатная открытая школьная информационная система, разработанная ЮНЕСКО и KORDIT. Она обеспечивает повседневное администрирование учебных заведений всех уровней — от детских садов до начальных и средних школ, профессиональных учебных заведений и университетов. Подробнее: [openemis.org](https://www.openemis.org) и [Справочник ресурсов](resources.ru.md).

### OpenEMIS Core

OpenEMIS Core — основной прикладной уровень на базе CakePHP с версионным REST API (`/api/v5/`). Core 5.13.0 — базовая версия данного дистрибутива, включающая 678 ресурсов и 3361 эндпоинтов. Поддерживаются более ранние версии 5.7–5.9. Документация: [api.openemis.org/core](https://api.openemis.org/core).

### MCP (Model Context Protocol)

MCP — открытый протокол, позволяющий ИИ-ассистентам (Claude, ChatGPT, Cursor, Cline) вызывать внешние инструменты как структурированные функции. openemis-mcp-pro реализует MCP через stdio (локальный подпроцесс) и HTTP (удалённый сервер), предоставляя девять инструментов для чтения и записи данных любого экземпляра OpenEMIS.

### Школьная информационная система (ШИС)

Школьная информационная система — программное обеспечение, централизующее административные записи учебного заведения: зачисление учеников, посещаемость, оценивание, персонал, инфраструктуру и отчётность. OpenEMIS — это рекомендованная ЮНЕСКО ШИС; openemis-mcp-pro — ИИ-мост для естественно-языкового доступа к её данным.

### Управление образованием

Управление образованием охватывает администрирование, планирование и надзор за учебными заведениями и системами образования — от отдельных школ до министерской отчётности. OpenEMIS поддерживает управление образованием на всех этих уровнях.

### Посещаемость учеников

Посещаемость учеников в OpenEMIS регистрируется по принципу «отсутствие по умолчанию означает присутствие»: в `student-attendance-marked-records` записываются только не присутствующие ученики (отсутствующий, опоздавший, оправданный). Ученик без строки за отмеченный день считается присутствующим. См. плейбуки [Отметка посещаемости учеников](playbooks/mark-student-attendance.ru.md) и [Просмотр последней посещаемости](playbooks/view-latest-attendance.ru.md).

### Посещаемость персонала

Посещаемость персонала охватывает два раздельных процесса: простая отметка о присутствии в `institution-staff-attendances` (с опциональным временем прихода/ухода) и заявка на отпуск в `institution-staff-leave` (контролируется workflow, требует одобрения руководителя). Таблицы разделены и объединяются на стороне клиента. См. [Отметка посещаемости персонала](playbooks/mark-staff-attendance.ru.md).

### Риски учеников / раннее предупреждение

OpenEMIS рассчитывает индивидуальные показатели риска на основе настраиваемых критериев (уровень посещаемости, успеваемость, инциденты поведения). При превышении порога срабатывают правила оповещений. Данные о рисках хранятся в `institution-student-risks`, `student-risks-criterias` и `risks`. См. [Просмотр профиля рисков ученика](playbooks/view-student-risks.ru.md) и [Просмотр сводки по рискам учреждения](playbooks/view-institution-risks.ru.md).

### Инцидент поведения

Инцидент поведения — зафиксированное дисциплинарное или социальное событие для ученика: категория (буллинг, нарушение дисциплины, забота о благополучии), уровень серьёзности, дата и меры реагирования. Записывается в `institution-student-behavior-records` через плейбук [Запись инцидента с поведением ученика](playbooks/record-behavior-incident.ru.md).

### Workflow / очередь приёма / очередь зачисления

OpenEMIS использует плагин CakePHP Workflow для управления многоэтапными процессами утверждения. Наиболее распространённый workflow — приём → зачисление: заявка ученика проходит этапы (подана, рассмотрена, одобрена) перед созданием активной записи о зачислении. Ресурсы под управлением workflow нельзя записывать напрямую через API. Для получения информации об этом используйте `openemis_get_playbook({ id: "explain-workflow-system" })`.

### Учреждение (детский сад, школа, вуз)

Учреждение в OpenEMIS — любое образовательное заведение: детские сады, начальные и средние школы, средние профессиональные учебные заведения, технические колледжи и университеты — все моделируются как `institutions` с `institution_type_id`. Публичный демо-сервер [demo.openemis.org](https://demo.openemis.org/core) включает 24 учреждения разных типов.

### Академический период

Академический период — именованный временной промежуток (учебный год, семестр, четверть), в рамках которого хранятся большинство данных OpenEMIS. Текущий период: `GET /api/v5/academic-periods?current=1`.

### Класс образования

Класс образования (например, 1-й, 10-й, 12-й классы) представляет уровень в системе образования. Классы определяются в `education-grades` и связаны с `education_system_id`. Учебные группы привязаны к классам; конфигурации типов отметки посещаемости и табелей успеваемости также привязаны к классам.

### Секция / учебная группа

Секция или учебная группа (`institution-classes`) — единица обучения с классным руководителем, классом образования, списком зачисленных учеников и набором предметов. Большинство запросов по посещаемости и расписанию привязаны к учебной группе. См. [Просмотр полного профиля класса](playbooks/view-class-profile.ru.md).

### Экзаменационная оценка / табель успеваемости

Экзаменационная оценка — числовой балл, записанный в `assessment-item-results` для одного ученика, одного элемента оценивания и одного академического периода. Совокупность оценок за период представляется в виде табеля успеваемости. См. [Ввод экзаменационных оценок](playbooks/submit-exam-marks.ru.md) и [Генерация табеля успеваемости](playbooks/generate-student-report-card-pdf.ru.md).

### Предмет / учебная программа

Предмет (`education-subjects`) — преподаваемая дисциплина (математика, естественные науки, язык). Предметы связаны с классами через учебную программу; набор активных предметов класса хранится в `institution-class-subjects`. Идентификаторы предметов нужны при отметке посещаемости в режимах SUBJECT и DAY_AND_SUBJECT.

### Плейбук

Плейбук в openemis-mcp-pro — пошаговое руководство для ИИ-агента: какие ресурсы вызывать, в каком порядке и с какими параметрами для выполнения реальной задачи управления образованием. В данном дистрибутиве 40 плейбуков — 26 для чтения и 14 для записи/авторизации. Загрузить плейбук: `openemis_get_playbook({ id: "id-плейбука" })`.

### Ресурс (в терминах MCP)

В openemis-mcp-pro ресурс — идентификатор в формате kebab-case, соответствующий одному семейству эндпоинтов OpenEMIS API: например `institution-students`, `student-attendance-marked-records` или `institution-assets`. Передаётся как параметр `resource` в инструменты `openemis_get`, `openemis_create`, `openemis_update` или `openemis_delete`. Полный список 678 ресурсов — в [Справочнике ресурсов](resources.ru.md).
