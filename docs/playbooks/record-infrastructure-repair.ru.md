# Запись ремонта или восстановления инфраструктуры в OpenEMIS

**Домен:** Инфраструктура  
**Аудитория:** администратор, бухгалтер, служба эксплуатации  
**ID руководства:** `record-infrastructure-repair`

## Описание

Зафиксируйте завершенный или текущий ремонт, восстановление или проект технического обслуживания в учреждении — восстановленные туалеты, починенная крыша, покрашенный класс, замененный водяной насос. Запись попадает в `infrastructure-needs`, который отслеживает полный жизненный цикл: когда проблема была выявлена, когда начались работы и когда они были завершены. НЕ передавайте поле `code` — оно генерируется сервером асинхронно (повторно запросите запись после создания, чтобы получить его).

---

## Вопросы, которые нужно задать вначале

| Вопрос | Поле | Примечания |
|---|---|---|
| Что было отремонтировано / восстановлено? | `name` | Краткое название, например, "Санузел Блок A — 2 туалета восстановлены" |
| Опишите выполненные работы | `description` | Детали: что заменено, подрядчик, объем работ |
| Когда проблема была впервые выявлена? | `date_determined` | ГГГГ-ММ-ДД, обязательно — не может быть в будущем |
| Когда начались работы? | `date_started` | ГГГГ-ММ-ДД, опционально |
| Когда работы были завершены? | `date_completed` | ГГГГ-ММ-ДД, опционально (оставьте null, если еще продолжаются) |
| Есть ли отчет или имя файла документа? | `file_name` | Опциональная строка-ссылка, например, `restoration_report.pdf` |

---

## Используемые ресурсы

| Ресурс | Назначение |
|---|---|
| `institution-buildings` | Чтение: найти соответствующую запись здания для справки (опционально) |
| `infrastructure-needs` | Запись: создать запись о ремонте/восстановлении |

---

## Шаги

| Шаг | Действие | Ресурс | Назначение |
|---|---|---|---|
| 1 | `openemis_get` | `institution-buildings` | Найти ID здания для контекстного описания (опционально) |
| 2 | `openemis_create` | `infrastructure-needs` | Зафиксировать ремонт со всеми полями дат |

---

## Примечания к шагам

**Шаг 1 — Поиск здания (Опционально)**  
Фильтруйте по `institution_id`, чтобы получить список зданий. Этот шаг только для контекстного описания — в документированном наборе полей `infrastructure-needs` не имеет жесткой внешней связи (FK) с `institution-buildings`. Используйте название здания в полях `name` и `description`, чтобы запись была отслеживаемой.

**Шаг 2 — Создание записи о ремонте**

Тело POST-запроса:
```json
{
  "name":            "Sanitation Block A — 2 Toilets Restored",
  "description":     "Replaced damaged cisterns and fixtures in 2 female toilets. Contractor: City Plumbers Ltd. Final inspection passed.",
  "date_determined": "2025-04-01",
  "date_started":    "2025-04-10",
  "date_completed":  "2025-04-15",
  "file_name":       "toilet_restoration_final_report.pdf"
}
```

Для **текущего ремонта** (работы еще не завершены) опустите `date_completed`:
```json
{
  "name":            "Roof Repair — Main Block",
  "description":     "Leaking roof over classrooms 3–5. Emergency repair in progress.",
  "date_determined": "2025-04-18",
  "date_started":    "2025-04-19"
}
```

Чтобы **завершить** текущую запись, используйте PUT с полным набором данных:
```json
PUT /institution-needs/{id}
{
  "name":            "Roof Repair — Main Block",
  "description":     "...(original text)...",
  "date_determined": "2025-04-18",
  "date_started":    "2025-04-19",
  "date_completed":  "2025-04-25",
  "file_name":       "roof_inspection_final.pdf"
}
```

> ⚠️ **НИКОГДА не передавайте `code` в теле POST-запроса.** Сервер генерирует его асинхронно. Ответ на POST может вернуть `code: null` — повторно запросите с помощью GET, чтобы получить сгенерированный код.

> ⚠️ **PUT требует полного набора данных.** Всегда запрашивайте текущую запись, объединяйте с новыми полями, а затем отправляйте PUT с полным объектом. Пропуск поля установит его значение в null.

---

## Ключевые подводные камни

- **`date_determined` обязательно и не может быть в будущем** — дата в будущем вызывает ошибку 422.
- **`code` генерируется автоматически** — не передавайте его в POST. Повторно запросите после создания, если вам нужно его отобразить.
- **В документированном интерфейсе нет обновления FK состояния для зданий.** Таблица поиска `infrastructure-conditions` существует, но эндпоинт `institution-buildings` не предоставляет `infrastructure_condition_id` в своем документированном интерфейсе для записи. НЕ пытайтесь отправлять PUT-запросы для обновления состояния зданий — поле будет проигнорировано или вызовет ошибку 422.
- **Нет `academic_period_id`** в этом ресурсе.

## Пример запроса

> *"Мы восстановили 2 туалета в блоке для девочек. Работы начались 10 апреля, завершились 15 апреля."*

1. `openemis_get { resource: "institution-buildings", params: { institution_id: 6 } }` → "Санузел для девочек" (id: 14)
2. `openemis_create { resource: "infrastructure-needs", body: { name: "Girls' Sanitation Block — 2 Toilets Restored", description: "Replaced cisterns and flush fittings in 2 female toilets. Block identified as Building 14.", date_determined: "2025-04-01", date_started: "2025-04-10", date_completed: "2025-04-15" } }`
