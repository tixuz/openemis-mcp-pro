# Определение моей личности (Кто я в OpenEMIS?)

**Домен:** Аутентификация
**Аудитория:** учитель, администратор, сотрудник
**ID руководства:** `resolve-my-identity`

## Описание

После того как пользователь вошел в систему с помощью `openemis_login({username, password})`, определите, кто он в терминах OpenEMIS: его `security_users.id`, полное имя, к каким учреждениям он прикреплен и какие роли/классы у него есть. Это мост между «я только что прошел аутентификацию» и «покажи мне мои данные» — без этого агент знает строку имени пользователя, но ничего не знает о том, что этот пользователь может видеть, преподавать или управлять.

Запустите это сразу после `openemis_login` (или в начале любой сессии, где пользователь ссылается на «мой», «мои», «меня»). Кэшируйте определенный идентификатор пользователя до конца разговора — не определяйте его заново на каждом шаге.

---

## Используемые ресурсы

| Ресурс | Назначение |
|---|---|
| `security-users` | Определение имени пользователя → идентификатор пользователя, имя/фамилия, email |
| `institution-staff` | Учреждения, где этот пользователь является активным сотрудником + FTE + должность |
| `institution-positions` | Определение `staff_position_title_id` → читаемое человеком название должности (учитель, директор, HR, …) |
| `institutions` | Определение названий учреждений по `institution_id` |
| `institution-classes` | Классы-группы для этого пользователя (`staff_id = user.id`) |
| `institution-classes-secondary-staff` | Второстепенные/совместно преподаваемые классы |
| `institution-subject-staff` | Предметы, которые преподает этот пользователь (одна строка на (класс, предмет, сотрудник)) |
| `security-group-users` | Членство в административных группах (район, регион, системные роли) |

---

## Шаги

| Шаг | Действие | Ресурс | Назначение |
|---|---|---|---|
| 1 | `openemis_whoami` | — | Прочитать имя пользователя текущей сессии |
| 2 | `openemis_get` | `security-users` | Имя пользователя → идентификатор пользователя + имя/фамилия |
| 3 | `openemis_get` | `institution-staff` | В каких учреждениях я являюсь сотрудником? |
| 4 | `openemis_get` | `institution-positions` | Определить мою должность в каждом учреждении |
| 5 | `openemis_get` × 3 | `institution-classes` · `institution-classes-secondary-staff` · `institution-subject-staff` | Классы, которые я преподаю (класс-группа + второстепенные + предмет) |
| 6 | Составление | — | Вернуть краткое описание «кто вы» в одном абзаце |

---

## Примечания к шагам

**Шаг 1 — Проверка сессии**
Вызовите `openemis_whoami` без аргументов. Если результат содержит `mode: "env-default"`, пользователь ЕЩЕ НЕ вызывал `openemis_login` — действующая личность — это пользователь из .env файла сервера, который может быть admin/admin на демо-инстансах. Предупредите, прежде чем считать это «реальной» личностью. Для сессий на пользователя ответ включает `username`.

**Шаг 2 — Имя пользователя → идентификатор пользователя**
`openemis_get('security-users', params: { _conditions: 'username:<username>', _fields: 'id,username,first_name,last_name,email,gender_id' })`. Возвращает ровно одну строку в правильно настроенном экземпляре OpenEMIS (имя пользователя уникально). Сохраните `id` — вы будете использовать его везде ниже. Если строк не вернулось, JWT для входа действителен, но запись пользователя была удалена — отобразите это как ошибку.

**Шаг 3 — Прикрепления к учреждениям**
`openemis_get('institution-staff', params: { _conditions: 'staff_id:<user_id>;staff_status_id:1', _fields: 'id,institution_id,institution_position_id,FTE,start_date,end_date', limit: 200 })`. `staff_status_id=1` фильтрует по статусу Назначен/Активен. Активный учитель обычно имеет одну или две строки (основное учреждение + дополнительное назначение). FTE — это десятичная строка ("1.00", "0.50"); преобразуйте в число с плавающей точкой, если нужно суммировать. Нет строк = у пользователя есть логин, но он нигде не назначен как сотрудник — часто так бывает для учетных записей администратора.

**Шаг 4 — Название должности**
Для каждого уникального `institution_position_id` из шага 3 получите строку должности, чтобы получить ее `staff_position_title_id`. Затем определите его по `staff-position-titles`, чтобы получить метку типа «Учитель», «Директор», «HR». Кэшируйте сопоставление названий на сессию — оно редко меняется. Пакетный запрос с `?ids=`:
`openemis_get('institution-positions', params: { ids: '<csv of position ids>' })`.

**Шаг 5 — Классы, которые я преподаю (тройное ветвление)**
Классы, связанные с этим пользователем, распределены по трем таблицам (такая же структура, как в шаге 5 `view-class-profile`):

(a) **Класс-группа** — `openemis_get('institution-classes', params: { _conditions: 'staff_id:<user_id>;academic_period_id:<current>', _fields: 'id,name,institution_id,education_grade_id,academic_period_id' })`. `staff_id` здесь — это внешний ключ на учителя класса-группы.

(b) **Второстепенный/совместный учитель** — `openemis_get('institution-classes-secondary-staff', params: { _conditions: 'security_user_id:<user_id>', _fields: 'id,institution_class_id' })`. Затем получите указанные строки `institution-classes` с помощью `?ids=`.

(c) **Учитель предмета** — `openemis_get('institution-subject-staff', params: { _conditions: 'security_user_id:<user_id>', _fields: 'id,institution_class_id,institution_subject_id' })`. Ветвление для определения названий классов + названий предметов с помощью двух пакетных вызовов `?ids=`.

Объедините три набора и удалите дубликаты по `institution_class_id`. Класс, где пользователь является И учителем класса-группы, И учителем предмета, должен появиться один раз, с перечислением обеих ролей.

**Шаг 6 — Краткое описание**
Составьте ответ в одном абзаце, например:

> Вы — **{first_name} {last_name}** (идентификатор пользователя {id}). Вы назначены **{position_title}** в **{institution_name}**{, а также в X, если несколько учреждений}. В этом учебном периоде у вас **{N}** классов: {class_1} (класс-группа), {class_2} (предмет: Математика), {class_3} (совместный учитель), …

Используйте это краткое описание как неявный контекст для любого последующего вопроса, который говорит «мои ученики», «мои классы», «мое учреждение» и т.д. — не запрашивайте эти данные заново на каждом шаге.

## Пример последовательности вызовов

```
1. openemis_login({ username: "teacher", password: "teacher" })
   → { ok: true, username: "teacher" }

2. openemis_whoami()
   → { mode: "per-user", username: "teacher", baseUrl: "https://demo.openemis.org/core" }

3. openemis_get("security-users", {
     params: { _conditions: "username:teacher", _fields: "id,first_name,last_name,email" }
   })
   → data: [{ id: 42, first_name: "Demo", last_name: "Teacher", email: "…" }]

4. openemis_get("institution-staff", {
     params: { _conditions: "staff_id:42;staff_status_id:1",
               _fields: "institution_id,institution_position_id,FTE" }
   })
   → data: [{ institution_id: 12, institution_position_id: 57, FTE: "1.00" }]

5. openemis_get("institution-classes", {
     params: { _conditions: "staff_id:42;academic_period_id:<current>",
               _fields: "id,name,education_grade_id" }
   })
   → data: [{ id: 203, name: "Grade 4 — Section A", education_grade_id: 8 }]
```

## Подводные камни и примечания

- **Личность по умолчанию из окружения.** Если пользователь пропустил `openemis_login`, `openemis_whoami` возвращает `mode: "env-default"`. НЕ получайте профиль ученика и не говорите «это ваш ребенок» в этом случае — это учетные данные администратора/демо сервера, а не реального пользователя. Попросите его сначала вызвать `openemis_login`.

- **Регистрозависимость имени пользователя.** `security_users.username` в OpenEMIS регистрозависим в соответствии с настройками сортировки MySQL по умолчанию в большинстве установок. Передавайте точную строку из `openemis_whoami`, а не ее версию в нижнем регистре.

- **Пользователи в нескольких учреждениях.** Директора, назначенные на кластер, или учителя с двойным назначением имеют >1 строк в `institution-staff`. Все последующие вопросы («мои ученики», «мои классы») становятся неоднозначными — спросите пользователя, какое учреждение он имеет в виду, или перечислите все, сгруппированные по учреждению.

- **Администраторы и непредметный персонал.** Пользователи, чья должность — «Директор», «HR» или «Секретарь», обычно будут иметь ноль строк в таблицах уровня классов (шаг 5). Это ожидаемо — их область — все учреждение, а не конкретный класс. Краткое описание должно читаться как «Вы — Директор X» без списка классов.

- **Текущий учебный период.** Шаг 5 фильтрует по `academic_period_id:<current>` — определите `<current>` через `GET academic-periods?current=1` один раз за сессию и кэшируйте его.

- **Срок действия JWT.** Если любой шаг возвращает HTTP 401, сохраненный JWT истек — MCP отобразит ошибку «пожалуйста, вызовите openemis_login снова». Это может произойти после длительных периодов бездействия; попросите пользователя пройти аутентификацию заново.

- **Конфиденциальность.** Краткое описание, которое вы составляете, становится неявным контекстом. Будьте кратки (имя + должность + учреждение + количество классов) — не выгружайте email, пол или дату найма в разговор, если пользователь явно не попросит об этом.
