# Record an Infrastructure Repair or Restoration

**Domain:** Infrastructure  
**Audience:** admin, accountant, facilities  
**Playbook ID:** `record-infrastructure-repair`

## Description

Log a completed or in-progress repair, restoration, or maintenance project at an institution — toilets restored, roof fixed, classroom repainted, water pump replaced. The record goes into `infrastructure-needs`, which tracks the full lifecycle: when the issue was identified, when work started, and when it was completed. Do NOT send the `code` field — it is auto-generated by the server asynchronously (re-fetch the record after creation to retrieve it).

---

## Questions to Ask First

| Question | Field | Notes |
|---|---|---|
| What was repaired / restored? | `name` | Short title, e.g. "Sanitation Block A — 2 Toilets Restored" |
| Describe the work done | `description` | Detail: what was replaced, contractor, scope |
| When was the problem first identified? | `date_determined` | YYYY-MM-DD, required — cannot be in the future |
| When did work start? | `date_started` | YYYY-MM-DD, optional |
| When was it completed? | `date_completed` | YYYY-MM-DD, optional (leave null if still ongoing) |
| Is there a report or document filename? | `file_name` | Optional reference string, e.g. `restoration_report.pdf` |

---

## Resources Used

| Resource | Purpose |
|---|---|
| `institution-buildings` | Read: find the relevant building record for reference (optional) |
| `infrastructure-needs` | Write: create the repair/restoration log entry |

---

## Steps

| Step | Action | Resource | Purpose |
|---|---|---|---|
| 1 | `openemis_get` | `institution-buildings` | Find the building ID for narrative reference (optional) |
| 2 | `openemis_create` | `infrastructure-needs` | Log the repair with all date fields |

---

## Step Notes

**Step 1 — Building Lookup (Optional)**  
Filter by `institution_id` to list buildings. This step is for narrative context only — `infrastructure-needs` does not have a hard FK to `institution-buildings` in the documented field set. Use the building name in the `name` and `description` fields to make the record traceable.

**Step 2 — Create Repair Record**

POST body:
```json
{
  "name":            "Sanitation Block A — 2 Toilets Restored",
  "description":     "Replaced damaged cisterns and fixtures in 2 female toilets. Contractor: City Plumbers Ltd. Final inspection passed.",
  "date_determined": "2025-04-01",
  "date_started":    "2025-04-10",
  "date_completed":  "2025-04-15",
  "file_name":       "toilet_restoration_final_report.pdf"
}
```

For an **ongoing repair** (work not yet complete), omit `date_completed`:
```json
{
  "name":            "Roof Repair — Main Block",
  "description":     "Leaking roof over classrooms 3–5. Emergency repair in progress.",
  "date_determined": "2025-04-18",
  "date_started":    "2025-04-19"
}
```

To **close out** an in-progress record, use PUT with the full payload:
```json
PUT /institution-needs/{id}
{
  "name":            "Roof Repair — Main Block",
  "description":     "...(original text)...",
  "date_determined": "2025-04-18",
  "date_started":    "2025-04-19",
  "date_completed":  "2025-04-25",
  "file_name":       "roof_inspection_final.pdf"
}
```

> ⚠️ **Never send `code` in the POST body.** The server generates it asynchronously. The POST response may return `code: null` — re-fetch with GET to retrieve the generated code.

> ⚠️ **PUT requires the full payload.** Always fetch the current record, merge the new fields, then PUT the complete object. Omitting a field sets it to null.

---

## Key Gotchas

- **`date_determined` is required and must not be in the future** — a future date causes 422.
- **`code` is auto-generated** — do not send on POST. Re-fetch after creation if you need to display it.
- **No condition FK update on buildings is documented.** The infrastructure-conditions lookup table exists but the `institution-buildings` endpoint does not expose `infrastructure_condition_id` in its documented write surface. Do not attempt to PUT condition updates on buildings — the field will be silently ignored or cause 422.
- **No `academic_period_id`** on this resource.

---

## Example Query

> *"We restored 2 toilets in the girls' block. Work started April 10, finished April 15."*

1. `openemis_get { resource: "institution-buildings", params: { institution_id: 6 } }` → "Girls' Sanitation Block" (id: 14)
2. `openemis_create { resource: "infrastructure-needs", body: { name: "Girls' Sanitation Block — 2 Toilets Restored", description: "Replaced cisterns and flush fittings in 2 female toilets. Block identified as Building 14.", date_determined: "2025-04-01", date_started: "2025-04-10", date_completed: "2025-04-15" } }`
