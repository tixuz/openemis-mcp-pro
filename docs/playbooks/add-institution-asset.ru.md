# Добавление оборудования или активов в учреждение

**Домен:** Инфраструктура  
**Аудитория:** администратор, бухгалтер, служба эксплуатации  
**ID руководства:** `add-institution-asset`

## Описание

Запись вновь приобретенного оборудования или активов в учреждении — компьютеры, парты, проекторы, мебель или любые предметы физической инвентаризации. Одна строка = один физический предмет; для добавления нескольких одинаковых единиц отправьте по одной записи на каждый предмет с уникальными `code` и `serial_number`. `purchase_order` и `cost` должны быть включены в каждую запись (присутствуют во всех задокументированных примерах — считайте их обязательными, даже если формально они не помечены как NOT NULL).

---

## Вопросы, которые нужно задать в первую очередь

Перед записью агент должен собрать:

| Вопрос | Поле | Примечания |
|---|---|---|
| Какой тип актива? (например, ноутбук, стул, проектор) | `description` | Произвольный текст — будьте описательны |
| Сколько единиц? | (количество циклов) | Один POST на единицу |
| Каков код актива / инвентарный ярлык? | `code` | Должен быть уникальным в масштабах всей системы, например `AST-2025-001` |
| Серийный номер(а)? | `serial_number` | Один на единицу; должен быть уникальным |
| Марка / производитель? | `asset_make_id` | Поиск через `asset-makes`; пропустите, если неизвестно |
| Модель? | `asset_model_id` | Поиск через `asset-models`; пропустите, если неизвестно |
| Номер заказа на покупку? | `purchase_order` | Ссылка на заказ, например `PO/2025/045` |
| Стоимость единицы? | `cost` | Числовое значение, например `1250.00` |

---

## Используемые ресурсы

| Ресурс | Назначение |
|---|---|
| `asset-makes` | Поиск: список производителей (Dell, HP и т.д.) |
| `asset-models` | Поиск: список моделей (опционально) |
| `institution-assets` | Запись: создание одной записи на физическую единицу |

---

## Шаги

| Шаг | Действие | Ресурс | Назначение |
|---|---|---|---|
| 1 | `openemis_get` | `asset-makes` | Определить ID производителя по названию → `asset_make_id` (пропустите, если марка неизвестна) |
| 2 | `openemis_get` | `asset-models` | Определить ID модели по названию → `asset_model_id` (пропустите, если модель неизвестна) |
| 3 | `openemis_create` × N | `institution-assets` | Отправить одну запись на физическую единицу |

---

## Примечания к шагам

**Шаги 1–2 — Поиск (Опционально)**  
Выполняйте только если пользователь предоставил марку или модель. Фильтруйте по названию: `GET /api/v5/asset-makes?name=Dell`. Если совпадений нет, продолжайте без внешнего ключа — оба поля являются необязательными. Некорректный `asset_make_id` будет отклонен с ошибкой 422, поэтому передавайте его только при наличии действительного ID.

**Шаг 3 — Создание записей об активах**

Тело POST на единицу:
```json
{
  "code":           "AST-2025-001",
  "description":    "Dell OptiPlex 3090 Desktop Computer",
  "serial_number":  "SN-DELL-9988776655",
  "purchase_order": "PO/2025/045",
  "cost":           1250.00,
  "asset_make_id":  12,
  "asset_model_id": 45
}
```

Для N единиц повторите с уникальными `code` (например, `AST-2025-001`, `AST-2025-002`) и уникальными `serial_number`.

> ⚠️ **PUT требует полный набор данных.** При обновлении существующего актива сначала получите текущую запись, объедините изменения, а затем отправьте PUT с полным объектом. Пропуск любого поля установит его значение в null.

## Ключевые подводные камни

- **Одна строка = один физический предмет.** Поля `quantity` не существует. «Мы купили 5 компьютеров» = 5 вызовов POST.
- **`code` должен быть уникальным в масштабах всей системы.** При совпадении возвращается ошибка 409. Предложите схему вида `{INSTITUTION_CODE}-{YEAR}-{SEQ}`, если у пользователя нет собственного соглашения.
- **`purchase_order` и `cost` присутствуют в каждом задокументированном примере** — включайте их в каждую запись.
- **`asset_make_id` и `asset_model_id` являются необязательными**, но если они передаются, это должны быть действительные ID — некорректное значение вызовет ошибку 422, а не будет проигнорировано.
- **Поля `academic_period_id` в этом ресурсе нет** — не передавайте его.

## Пример запроса

> *«Мы купили 2 ноутбука Dell для библиотеки — серийные номера SN-001 и SN-002, стоимость 1100 каждый, PO/2025/071.»*

1. `openemis_get { resource: "asset-makes", params: { name: "Dell" } }` → id: 12
2. `openemis_create { resource: "institution-assets", body: { code: "LIB-2025-001", description: "Dell Laptop", serial_number: "SN-001", purchase_order: "PO/2025/071", cost: 1100.00, asset_make_id: 12 } }`
3. `openemis_create { resource: "institution-assets", body: { code: "LIB-2025-002", description: "Dell Laptop", serial_number: "SN-002", purchase_order: "PO/2025/071", cost: 1100.00, asset_make_id: 12 } }`
