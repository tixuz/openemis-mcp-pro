# إضافة معدات أو أصول لمؤسسة

**المجال:** البنية التحتية  
**الجمهور:** مدير، محاسب، مرافق  
**معرف دليل التشغيل:** `add-institution-asset`

## الوصف

تسجيل المعدات أو الأصول المكتسبة حديثًا في مؤسسة — أجهزة كمبيوتر، مكاتب، عارضات، أثاث، أو أي عنصر من عناصر المخزون المادي. صف واحد = عنصر مادي واحد؛ لإضافة وحدات متطابقة متعددة، أرسل سجلًا واحدًا لكل عنصر برقم `code` و `serial_number` مميزين. يجب تضمين `purchase_order` و `cost` في كل عملية كتابة (موجودان في جميع الأمثلة الموثقة — اعتبارهما مطلوبين حتى لو لم يكونا قابلين للإلغاء رسميًا).

---

## أسئلة يجب طرحها أولاً

قبل كتابة أي شيء، يجب على الوكيل جمع:

| السؤال | الحقل | ملاحظات |
|---|---|---|
| ما نوع الأصل؟ (مثل: كمبيوتر محمول، كرسي، عارضة) | `description` | نص حر — كن وصفيًا |
| كم عدد الوحدات؟ | (عدد الحلقات) | طلب POST واحد لكل وحدة |
| ما هو رمز الأصل / بطاقة الجرد؟ | `code` | يجب أن يكون فريدًا على مستوى النظام، مثل `AST-2025-001` |
| رقم/أرقام التسلسل؟ | `serial_number` | واحد لكل وحدة؛ يجب أن يكون فريدًا |
| الصانع / الشركة المصنعة؟ | `asset_make_id` | البحث عبر `asset-makes`؛ تخطى إذا كان غير معروف |
| الموديل؟ | `asset_model_id` | البحث عبر `asset-models`؛ تخطى إذا كان غير معروف |
| رقم أمر الشراء؟ | `purchase_order` | مرجع أمر الشراء، مثل `PO/2025/045` |
| تكلفة الوحدة؟ | `cost` | رقمي، مثل `1250.00` |

---

## الموارد المستخدمة

| المورد | الغرض |
|---|---|
| `asset-makes` | بحث: قائمة الشركات المصنعة (Dell، HP، إلخ.) |
| `asset-models` | بحث: قائمة الموديلات (اختياري) |
| `institution-assets` | كتابة: إنشاء سجل واحد لكل وحدة مادية |

---

## الخطوات

| الخطوة | الإجراء | المورد | الغرض |
|---|---|---|---|
| 1 | `openemis_get` | `asset-makes` | تحويل اسم الصانع → `asset_make_id` (تخطى إذا كان الصانع غير معروف) |
| 2 | `openemis_get` | `asset-models` | تحويل اسم الموديل → `asset_model_id` (تخطى إذا كان الموديل غير معروف) |
| 3 | `openemis_create` × N | `institution-assets` | إرسال سجل واحد لكل وحدة مادية |

---

## ملاحظات الخطوات

**الخطوة 1–2 — عمليات البحث (اختياري)**  
قم بتشغيلها فقط إذا قدم المستخدم اسم صانع أو موديل. قم بالتصفية حسب الاسم: `GET /api/v5/asset-makes?name=Dell`. إذا لم يكن هناك تطابق، تابع بدون المفتاح الأجنبي — كلا الحقلين اختياريان. سيتم رفض `asset_make_id` غير الصالح مع خطأ 422، لذا أرسله فقط عندما يكون لديك معرف صالح.

**الخطوة 3 — إنشاء سجلات الأصول**

نص طلب POST لكل وحدة:
```json
{
  "code":           "AST-2025-001",
  "description":    "Dell OptiPlex 3090 Desktop Computer",
  "serial_number":  "SN-DELL-9988776655",
  "purchase_order": "PO/2025/045",
  "cost":           1250.00,
  "asset_make_id":  12,
  "asset_model_id": 45
}
```

لعدد N من الوحدات، كرر مع `code` فريد (مثل `AST-2025-001`، `AST-2025-002`) و `serial_number` فريد.

> ⚠️ **يتطلب PUT الحمولة الكاملة.** إذا كنت تقوم بتحديث أصل موجود، قم باسترجاع السجل الحالي أولاً، ادمج التغييرات، ثم أرسل الكائن الكامل عبر PUT. حذف أي حقل يجعله فارغًا (null).

## المزالق الرئيسية

- **صف واحد = عنصر مادي واحد.** لا يوجد حقل `quantity`. "اشترينا 5 أجهزة كمبيوتر" = 5 طلبات POST.
- **يجب أن يكون `code` فريدًا على مستوى النظام.** يؤدي التكرار إلى إرجاع خطأ 409. اقترح مخططًا مثل `{INSTITUTION_CODE}-{YEAR}-{SEQ}` إذا لم يكن لدى المستخدم اتفاقية موجودة.
- **يوجد `purchase_order` و `cost` في كل مثال موثق** — قم بتضمينهما في كل عملية كتابة.
- **`asset_make_id` و `asset_model_id` اختياريان** ولكن يجب أن يكونا معرفات صالحة إذا تم إرسالهما — القيمة غير الصالحة تسبب خطأ 422، وليس تخطيًا صامتًا.
- **لا يوجد `academic_period_id`** في هذا المورد — لا ترسله.

## مثال على الاستعلام

> *"اشترينا 2 كمبيوتر محمول من Dell للمكتبة — أرقام تسلسل SN-001 و SN-002، التكلفة 1,100 لكل منهما، PO/2025/071."*

1. `openemis_get { resource: "asset-makes", params: { name: "Dell" } }` → id: 12
2. `openemis_create { resource: "institution-assets", body: { code: "LIB-2025-001", description: "Dell Laptop", serial_number: "SN-001", purchase_order: "PO/2025/071", cost: 1100.00, asset_make_id: 12 } }`
3. `openemis_create { resource: "institution-assets", body: { code: "LIB-2025-002", description: "Dell Laptop", serial_number: "SN-002", purchase_order: "PO/2025/071", cost: 1100.00, asset_make_id: 12 } }`
