# OpenEMIS में एक इंफ्रास्ट्रक्चर मरम्मत या पुनर्स्थापना रिकॉर्ड करें

**डोमेन:** इंफ्रास्ट्रक्चर  
**दर्शक:** प्रशासक, लेखाकार, सुविधाएँ  
**प्लेबुक ID:** `record-infrastructure-repair`

## विवरण

किसी संस्थान में पूर्ण या प्रगति में मरम्मत, पुनर्स्थापना या रखरखाव परियोजना लॉग करें — शौचालय पुनर्स्थापित, छत ठीक, कक्षा पुनः रंगी, पानी का पंप बदला गया। रिकॉर्ड `infrastructure-needs` में जाता है, जो पूर्ण जीवनचक्र ट्रैक करता है: समस्या कब पहचानी गई, काम कब शुरू हुआ और कब पूरा हुआ। `code` फ़ील्ड न भेजें — यह सर्वर द्वारा अतुल्यकालिक रूप से स्वचालित रूप से जनरेट होता है (बनाने के बाद रिकॉर्ड को पुनः प्राप्त करने के लिए उसे फिर से फ़ेच करें)।

---

## पहले पूछने के प्रश्न

| प्रश्न | फ़ील्ड | नोट्स |
|---|---|---|
| क्या मरम्मत/पुनर्स्थापना हुई? | `name` | संक्षिप्त शीर्षक, जैसे "सैनिटेशन ब्लॉक A — 2 शौचालय पुनर्स्थापित" |
| किए गए कार्य का वर्णन करें | `description` | विवरण: क्या बदला गया, ठेकेदार, कार्यक्षेत्र |
| समस्या पहली बार कब पहचानी गई? | `date_determined` | YYYY-MM-DD, आवश्यक — भविष्य में नहीं हो सकता |
| काम कब शुरू हुआ? | `date_started` | YYYY-MM-DD, वैकल्पिक |
| यह कब पूरा हुआ? | `date_completed` | YYYY-MM-DD, वैकल्पिक (यदि अभी भी चल रहा है तो null छोड़ दें) |
| क्या कोई रिपोर्ट या दस्तावेज़ फ़ाइलनाम है? | `file_name` | वैकल्पिक संदर्भ स्ट्रिंग, जैसे `restoration_report.pdf` |

## उपयोग किए गए संसाधन

| संसाधन | उद्देश्य |
|---|---|
| `institution-buildings` | पढ़ें: संदर्भ के लिए प्रासंगिक बिल्डिंग रिकॉर्ड ढूंढें (वैकल्पिक) |
| `infrastructure-needs` | लिखें: मरम्मत/पुनर्स्थापना लॉग एंट्री बनाएं |

---

## चरण

| चरण | क्रिया | संसाधन | उद्देश्य |
|---|---|---|---|
| 1 | `openemis_get` | `institution-buildings` | कथा संदर्भ के लिए बिल्डिंग ID ढूंढें (वैकल्पिक) |
| 2 | `openemis_create` | `infrastructure-needs` | सभी दिनांक फ़ील्ड्स के साथ मरम्मत लॉग करें |

---

## चरण नोट्स

**चरण 1 — बिल्डिंग लुकअप (वैकल्पिक)**  
`institution_id` द्वारा फ़िल्टर करके बिल्डिंग्स की सूची बनाएं। यह चरण केवल कथा संदर्भ के लिए है — `infrastructure-needs` में दस्तावेज़ित फ़ील्ड सेट में `institution-buildings` के लिए कोई हार्ड FK नहीं है। रिकॉर्ड को ट्रेस करने योग्य बनाने के लिए `name` और `description` फ़ील्ड्स में बिल्डिंग नाम का उपयोग करें।

**चरण 2 — मरम्मत रिकॉर्ड बनाएं**

POST बॉडी:
```json
{
  "name":            "सैनिटेशन ब्लॉक A — 2 शौचालय पुनर्स्थापित",
  "description":     "2 महिला शौचालयों में क्षतिग्रस्त सिस्टर्न और फिक्स्चर बदले गए। ठेकेदार: सिटी प्लंबर्स लिमिटेड। अंतिम निरीक्षण पास।",
  "date_determined": "2025-04-01",
  "date_started":    "2025-04-10",
  "date_completed":  "2025-04-15",
  "file_name":       "toilet_restoration_final_report.pdf"
}
```

एक **चल रही मरम्मत** (काम अभी पूरा नहीं हुआ) के लिए, `date_completed` छोड़ दें:
```json
{
  "name":            "छत मरम्मत — मुख्य ब्लॉक",
  "description":     "कक्षाओं 3–5 के ऊपर छत से रिसाव। आपातकालीन मरम्मत प्रगति में।",
  "date_determined": "2025-04-18",
  "date_started":    "2025-04-19"
}
```

एक प्रगति में रिकॉर्ड को **समाप्त करने** के लिए, पूर्ण पेलोड के साथ PUT का उपयोग करें:
```json
PUT /institution-needs/{id}
{
  "name":            "छत मरम्मत — मुख्य ब्लॉक",
  "description":     "...(मूल पाठ)...",
  "date_determined": "2025-04-18",
  "date_started":    "2025-04-19",
  "date_completed":  "2025-04-25",
  "file_name":       "roof_inspection_final.pdf"
}
```

> ⚠️ **POST बॉडी में `code` कभी न भेजें।** सर्वर इसे अतुल्यकालिक रूप से जनरेट करता है। POST प्रतिक्रिया `code: null` लौटा सकती है — जनरेट किए गए कोड को पुनः प्राप्त करने के लिए GET के साथ फिर से फ़ेच करें।

> ⚠️ **PUT के लिए पूर्ण पेलोड आवश्यक है।** हमेशा वर्तमान रिकॉर्ड फ़ेच करें, नई फ़ील्ड्स को मर्ज करें, फिर पूर्ण ऑब्जेक्ट PUT करें। किसी फ़ील्ड को छोड़ने से वह null सेट हो जाती है।

## प्रमुख सावधानियाँ

- **`date_determined` आवश्यक है और भविष्य में नहीं हो सकता** — भविष्य की तारीख 422 का कारण बनती है।
- **`code` स्वचालित रूप से जनरेट होता है** — POST पर न भेजें। यदि आपको इसे प्रदर्शित करने की आवश्यकता है तो बनाने के बाद पुनः फ़ेच करें।
- **बिल्डिंग्स पर कोई कंडीशन FK अपडेट दस्तावेज़ित नहीं है।** इंफ्रास्ट्रक्चर-कंडीशंस लुकअप टेबल मौजूद है लेकिन `institution-buildings` एंडपॉइंट अपने दस्तावेज़ित राइट सतह पर `infrastructure_condition_id` एक्सपोज़ नहीं करता है। बिल्डिंग्स पर कंडीशन अपडेट PUT करने का प्रयास न करें — फ़ील्ड चुपचाप अनदेखी की जाएगी या 422 का कारण बनेगी।
- **इस संसाधन पर कोई `academic_period_id` नहीं**।

1. `openemis_get { resource: "institution-buildings", params: { institution_id: 6 } }` → "लड़कियों का सैनिटेशन ब्लॉक" (id: 14)
2. `openemis_create { resource: "infrastructure-needs", body: { name: "लड़कियों का सैनिटेशन ब्लॉक — 2 शौचालय पुनर्स्थापित", description: "2 महिला शौचालयों में सिस्टर्न और फ्लश फिटिंग्स बदली गईं। ब्लॉक को बिल्डिंग 14 के रूप में पहचाना गया।", date_determined: "2025-04-01", date_started: "2025-04-10", date_completed: "2025-04-15" } }`
